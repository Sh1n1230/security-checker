# ADR 0008: baseline の秘密は、候補 ID ではなく baseline のソルト付き要約で照合する

- 状態: 採用
- 日付: 2026-11-04
- 関連: #158

## 背景

gitleaks の候補 ID はマスク後の文字列から作るので、先頭 4 文字が同じ秘密は同じ ID になる。
そのため baseline に入れた秘密を同じ場所で別の秘密に差し替えると、新しい秘密も抑制される。

## 決定

候補 ID は変えない。baseline (version 2) に、ファイルごとのソルト `salt` と、
エントリごとの `secret_hash = sha256(salt + 0x00 + sha256(秘密の値))` を記録し、照合時に値も比べる。

- ID が一致しても `secret_hash` が違えば抑制せず、値を書かない警告を出す。
- 候補が持つ値の sha256 (`Candidate.secret_digest`) はレポート・ログ・LLM に出さない。
- version 1 の baseline は従来どおり ID だけで照合し、`baseline update` を促す警告を出す。

## 検討した案

ID に秘密の sha256 を混ぜる案は採らなかった。ID はレポート・SARIF・PR コメントに出るため、
短いパスワードは総当たりで戻せる。また、全 gitleaks 候補の ID と既存の alert の対応が変わる。

## 帰結

baseline をコミットするリポジトリでは、ソルトも同じファイルにあるので、低エントロピーの値は
baseline から総当たりで確かめられる。ソルトが防ぐのは、事前計算と別リポジトリとの突き合わせまでである。
もともとそのリポジトリにコミットされていた値なので、新しく漏らす情報は無いと判断した。
