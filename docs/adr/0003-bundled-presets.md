# 0003. 同梱プリセットは客観条件を満たすものだけ

- 状態: 採用 (2026-09-15。NEXT-STEPS の D11)
- 関連: DESIGN.md §9.7「同梱プリセットの採否基準」, §9.8

## 背景

プリセット (名前 → 方言・コマンド・capability) を同梱すると導入は楽になるが、
同梱されたものが事実上の「推奨」に見え、ベンダー中立性 (P5) が崩れる。

## 決定

- 同梱するのは §9.7 の客観条件 (非対話で動く・構造化出力を返せる・読み取り専用にできる、など) を
  満たすものだけ。D11 で対象にしたのは `process`: codex CLI・claude CLI、`http`: OpenAI 互換
  エンドポイント。2026-10-04 時点で同梱しているのは `process/claude.yml` と `http/openai.yml`
  (codex CLI は条件の確認待ち)。
- 一覧はアルファベット順で、順位や推奨マークを付けない。
- プリセットが 1 つも無くても `command:` を直接書けば同じように動くことを保証する (契約テストで確認)。

## 結果

- 条件を満たす新しいものは、YAML 1 ファイルの PR で足せる。
- 「対応 LLM 一覧」という表は作らない。載っていないものが使えないと読まれるため。
