# 0011. スキャナの版と sha256 をリポジトリに固定する

- 状態: 採用 (2026-10-10。記録は 2026-11-17)
- 関連: [0005](0005-composite-action-until-ghcr.md) の「決定」のうち「公式のチェックサムで検証する」を置き換える。
  `scripts/scanner-versions.sh`、docs/scanners.md

## 背景

0005 は、composite action がスキャナを実行時に取得し、公式のチェックサム (同じリリースに置かれた
チェックサムファイル) で検証すると決めた。

同じリリースのチェックサムファイルは、**リリースごと差し替えられた場合に役に立たない。** 配布物と
チェックサムを一緒に置き換えれば検証は通る。2026-03 の trivy v0.69.4 がこの経路だった。
また、action・自リポジトリの CI・Dockerfile がそれぞれ別の方法でスキャナを入れていて、経路ごとに版が
食い違っていた。

## 決定

- 版と sha256 (amd64 / arm64) を `scripts/scanner-versions.sh` の 1 か所に書く。sha256 はリリースから取らず、
  このリポジトリのコミットとして固定する。
- action・自リポジトリの workflow・Dockerfile は、すべて `scripts/install-scanners.sh` 経由でこれを読む。
- 更新するときは、公開から 7 日以上経った版を選び、公式のチェックサムと実際にダウンロードしたファイルの
  sha256 が一致することを確かめてから書き換える。
- 利用者が版を上書きした場合 (`gitleaks-version` などの入力) だけは、固定した値が無いので、
  リリース側のチェックサムで検証する。
- semgrep は Python のパッケージなので、`scripts/semgrep-requirements.txt` にハッシュ付きで固定する。

## 結果

- スキャナの更新は手作業になる。自動で提案する仕組みは #649 で検討している。
- 版を上書きした利用者は、リリースごとの差し替えに対しては守られない (文書に明記する)。
